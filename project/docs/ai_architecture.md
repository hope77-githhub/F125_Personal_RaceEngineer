# F1 AI Race Engineer - AI Architecture & Phase 3 Plan

본 문서는 F1 AI Race Engineer 프로젝트의 핵심 아키텍처, 특히 수동적인 데이터 처리(Rule-based)와 능동적인 AI(LLM)의 역할 분담에 대해 정의합니다.

## 1. 아키텍처 개요 (AI vs 수학적 알고리즘)

"AI 레이스 엔지니어"라는 명칭을 사용하지만, 전체 시스템이 처음부터 끝까지 머신러닝으로 구동되는 것은 아닙니다. 시스템의 정확도와 실시간성(Real-time)을 확보하기 위해 **수학적 알고리즘과 생성형 AI(LLM)가 각자의 강점을 발휘하도록 역할을 분담**합니다.

작동 방식은 다음 3단계로 이루어집니다.

### Step 1: 코너 추출 및 수치 계산 (수학적 알고리즘 / Data Processing)
- **역할:** F1 게임 물리 엔진에서 발생시킨 원시 데이터(Raw Telemetry)를 분석하여 주행 이벤트를 정량화합니다.
- **방식 (Non-AI):** 
  - 0.01초 단위로 쏟아지는 수만 개의 좌표와 텔레메트리 데이터를 분석하는 데에는 수학적 조건부(Rule-based) 알고리즘이 훨씬 빠르고 정확합니다.
  - 예: `횡가속도(Lateral G-Force) > 1.5G` 이고 `스티어링(Steering) > 0` 인 구간을 '코너'로 인식.
  - 해당 구간 내 최저 속도 지점을 'Apex', 브레이크 압력이 올라가는 시점을 'Braking Point'로 추출.
- **결과물:** 정량화된 팩트 데이터 (예: "Turn 1에서 유저는 앞차보다 20m 일찍 브레이크를 밟았고, Apex 속도는 15km/h 느림")

### Step 2: 주행 분석 및 전략 수립 (생성형 AI / LLM)
- **역할:** Step 1에서 뽑아낸 '차가운 숫자 데이터'를 인간 엔지니어처럼 분석하고 해석하여 드라이버에게 필요한 맞춤형 조언을 생성합니다.
- **방식 (Generative AI):**
  - 추출된 데이터를 JSON 프롬프트 형태로 거대 언어 모델(OpenAI GPT, Anthropic Claude, Google Gemini 등)에 전송.
  - 타이어 마모도, 남은 랩 수, 현재 순위 등의 복합적인 상황을 LLM이 종합적으로 판단.
- **결과물:** 자연어 기반의 브리핑 대본 (예: "Turn 1 진입 시 브레이킹이 너무 이릅니다. 진입 속도를 더 살려서 코너 정점(Apex)을 공략하세요.")

### Step 3: 실시간 음성 무전 (음성 합성 AI / TTS)
- **역할:** 레이스 중 화면을 볼 수 없는 드라이버를 위해 텍스트 기반의 조언을 음성으로 변환합니다.
- **방식 (TTS AI):**
  - 생성된 텍스트 대본을 ElevenLabs나 브라우저 내장 Web Speech API 등을 이용해 음성으로 합성.
  - 실제 F1 엔지니어 페르소나(예: Max Verstappen의 엔지니어 GP, Lewis Hamilton의 Bono 등)의 목소리와 무전기 노이즈 필터를 적용해 현실감을 극대화.

## 2. 개발 진행 상황 (Phases)

### Phase 1: 섹터 기반 비교 분석 (완료)
- `Packet 11 (Session History)` 연동 및 파싱 (CTypes LittleEndianStructure 적용)
- 특정 랩의 섹터 1/2/3 시간을 추출하여 라이벌/선두와 초 단위(Delta) 비교 구현
- 프론트엔드에 섹터별 기록 및 막대형 차트(Bar Chart) UI 구현 완료

### Phase 2: 서킷 모양 및 모션 데이터 시각화 (완료)
- `Packet 0 (Motion Data)` 연동 및 파싱
- 차량의 X, Z 월드 좌표(`m_worldPositionX/Z`)를 실시간으로 수집하여 프론트엔드로 전달
- 수집된 좌표를 바탕으로 SVG 기반의 2D 서킷 미니맵 렌더링 구현 및 섹터 시작점 표기 완료

### Phase 3: 코너 자동 인식 알고리즘 구현 (예정)
- 수집된 모션 데이터의 `m_gForceLateral` 및 텔레메트리 데이터의 `m_steer`, `m_brake`, `m_speed`를 활용
- **목표:** 트랙 정보를 하드코딩하지 않고, 물리적 움직임 패턴만으로 코너의 진입점, Apex, 탈출점을 100% 자동 추출하는 Rule-based 시스템 구축.
